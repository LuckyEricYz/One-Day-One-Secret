# 性能策略

> 当前目标是让 MVP 在普通手机和微信内浏览器中稳定可用。

## 1. 指标目标

| 指标 | 目标 |
|:-----|:-----|
| 首屏可交互时间 | `< 2.5s` |
| LCP | `< 2.5s` |
| CLS | `< 0.1` |
| 初始 JS 体积 gzip | `< 170KB` |
| `/api/generate` P95 | `< 4s` |

## 2. 首屏控制

- 首页只加载问卷、状态选择、长按所需资源
- 结果页和长图导出逻辑延迟加载
- 不在首屏请求非必要纹理、动画或分享能力
- 字体采用自托管或系统回退，不依赖外部字体 CDN

## 3. 代码拆分

建议拆分为：

- `home` chunk
- `result` chunk
- `history` chunk
- `image-export` chunk

延迟加载：

- `html2canvas`
- 历史页
- 分享相关逻辑

## 4. 动效降级

### 4.1 默认策略

- 长按反馈优先使用 CSS transform 或轻量 canvas
- 非关键动画用 `opacity` 和 `transform`
- 禁止用大量 DOM 粒子堆动画

### 4.2 降级规则

满足任一条件则关闭粒子效果，改为环形进度：

- `navigator.hardwareConcurrency <= 2`
- `navigator.deviceMemory <= 2`
- 首次检测到帧率持续低于 30fps

## 5. API 侧性能

- 先计算上下文，再调用模型，避免二次请求
- OpenAI 失败后只切备用平台 1 次
- fallback 模板本地可直接返回，不再链式重试
- 天气信息获取失败直接忽略，不阻塞生成

## 6. H5 注意事项

- 使用 `dvh` 或安全的视口方案，避免 iOS `100vh` 问题
- 微信内浏览器只保证保存图和长按链路，不额外依赖原生分享
- `navigator.vibrate` 仅做增强，不作为交互必要条件

## 7. 验收清单

- [ ] 首次进入问卷页无明显卡顿
- [ ] 状态选择到长按页切换小于 350ms
- [ ] 结果页在普通网络下 4 秒内可见
- [ ] 低端设备能自动降级长按效果
- [ ] 保存长图逻辑不会拖慢首屏
