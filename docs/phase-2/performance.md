# 性能策略

> 当前目标是让纸本视觉和粒子成卦在普通手机与桌面浏览器里都稳定运行。

## 1. 指标目标

| 指标 | 目标 |
|:-----|:-----|
| 首屏可交互时间 | `< 2.5s` |
| LCP | `< 2.5s` |
| CLS | `< 0.1` |
| 首页 JS gzip | `< 170KB` |
| `/api/generate` P95 | `< 4s` |

## 2. 首屏控制

- 首屏只加载问卷、状态选择、粒子成卦所需资源
- 结果导出逻辑继续延迟加载 `html2canvas`
- 纸面纹理用 CSS 渐变与轻量噪点，不请求大图贴图
- 外部字体 CDN 仍然禁用

## 3. 动效策略

### 3.1 默认策略

- 粒子球统一使用轻量 `canvas`
- 页面转场仍以 `opacity` + `transform` 为主
- 即时卦象在前端本地计算，不等待接口

### 3.2 Web / H5 分层

- Web：更高粒子数、hover 扰动、侧向预览滑入
- H5：更低粒子数、长按进度环、单列转场

### 3.3 降级规则

满足任一条件则自动进入轻量模式：

- `prefers-reduced-motion: reduce`
- `navigator.hardwareConcurrency <= 2`
- `navigator.deviceMemory <= 2`

轻量模式下：

- 粒子数降低
- 去掉 hover 扰动
- 保留成卦线条和纸面过渡，不保留复杂漂移

## 4. API 侧性能

- 卦象与时间种子在前端确定，服务端直接复用
- 默认先走 `hybrid` 检索，索引不可用自动回退 `rules`
- Provider 生成仍维持最多 2 次结构修复重试
- 所有 provider 不可用时直接回本地 fallback

## 5. H5 注意事项

- 使用 `dvh` 与安全区 padding 规避 iOS 视口问题
- `navigator.vibrate` 只做增强，不是必要交互
- 微信内浏览器只保证长按、补录、结果导出链路

## 6. 验收清单

- [ ] 首次进入问卷页无明显卡顿
- [ ] 状态选择到成卦页切换小于 350ms
- [ ] H5 长按 2 秒内反馈清晰，未完成时提示可见
- [ ] Web 点击后即时出现卦象预览
- [ ] 低性能设备自动降低粒子复杂度
- [ ] 保存长图不会拖慢首屏
