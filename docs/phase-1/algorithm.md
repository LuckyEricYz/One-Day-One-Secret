## 1. 二十四节气计算引擎

### 1.1 算法原理

节气是太阳在黄道上的位置决定的。太阳从春分点出发，每运行 15°为一个节气，全年共 24 个节气。

```
春分 = 0°   清明 = 15°   谷雨 = 30°   立夏 = 45°  ...
```

### 1.2 计算方法：寿星公式（高精度）

使用天文学「寿星公式」计算节气精确时间，误差小于 1 分钟：

```
公式：[Y × D + C] - L

- Y = 年份后两位数
- D = 0.2422（回归年天数除以节气数的系数）
- C = 世纪常数（21 世纪各节气有固定值）
- L = 闰年修正值 = INT(Y / 4)
```

### 2.2 计算公式

#### 年干支
```
年干 = (年份 - 4) % 10  → 映射到天干数组
年支 = (年份 - 4) % 12  → 映射到地支数组
```

#### 月干支
```
月支固定：正月=寅, 二月=卯, ... (需根据节气划分月份)
月干 = (年干 × 2 + 月份) % 10
```

#### 日干支
```
使用基姆拉尔森公式或查表法：
从已知基准日（如 1900年1月1日 = 甲子日）推算天数差
日干 = (基准干 + 天数差) % 10
日支 = (基准支 + 天数差) % 12
```

#### 时辰干支
```
时支 = 根据当前小时映射（见上表）
时干 = (日干 × 2 + 时支序号) % 10
```

## 3. 六十四卦起卦算法

### 3.1 卦象基础

**八卦（三爻）**：
| 卦 | 符号 | 二进制 | 五行 | 自然 |
|:---|:-----|:-------|:-----|:-----|
| 乾 | ☰ | 111 | 金 | 天 |
| 兑 | ☱ | 110 | 金 | 泽 |
| 离 | ☲ | 101 | 火 | 火 |
| 震 | ☳ | 100 | 木 | 雷 |
| 巽 | ☴ | 011 | 木 | 风 |
| 坎 | ☵ | 010 | 水 | 水 |
| 艮 | ☶ | 001 | 土 | 山 |
| 坤 | ☷ | 000 | 土 | 地 |

**六十四卦 = 上卦（外卦）+ 下卦（内卦）**，每卦由 6 个爻组成。

### 3.2 起卦算法（数字起卦法）

核心思路：将用户交互产生的「熵」映射为卦象。

```
输入：
  - pressDuration: 用户长按时长（毫秒）
  - timestamp: 当前时间戳（毫秒）
  - touchEntropy: 触摸坐标的微小偏移（可选，增加随机性）

算法步骤：
  1. 混合种子 = pressDuration × 7 + timestamp % 100000 + touchEntropy
  2. 使用种子生成 6 个爻值：
     - 对于第 i 个爻（i = 0..5）：
       value_i = hash(seed, i) % 4
       - 0: 老阴（变爻，阴 → 阳）
       - 1: 少阳（阳爻，不变）
       - 2: 少阴（阴爻，不变）
       - 3: 老阳（变爻，阳 → 阴）
  3. 本卦 = 6 个爻的当前状态
  4. 变卦 = 将变爻翻转后的卦象
  5. 互卦 = 取 2-4 爻为下卦，3-5 爻为上卦

hash 函数：
  使用简单的线性同余生成器（LCG）：
  hash(seed, i) = (seed * 1103515245 + 12345 + i * 16807) & 0x7fffffff
```

### 3.3 为什么用变爻

- **本卦**：代表当前状态
- **变卦**：代表事态发展趋势
- 有变爻 = 事在变化中，给出的建议更具动态性
- 无变爻 = 状态稳定，建议偏向维持

## 4. 三维加权聚合算法

### 4.1 权重体系

天地人三个维度对最终输出的影响权重：

```
默认权重：
  天（节气 + 干支）    = 0.35
  地（卦象 + 知识库）  = 0.35
  人（体质 + 今日状态）= 0.30

动态调整规则：
  - 节气交界前后 3 天：天的权重上调至 0.45，地降至 0.30
  - 用户有明确不适标签：人的权重上调至 0.40，天降至 0.30
  - 卦象有变爻：地的权重上调至 0.40（变化中的势更重要）
```

### 4.2 聚合为 Prompt 的逻辑

```
1. 根据权重决定 Prompt 中各维度信息的详细程度
2. 高权重维度：提供更丰富的上下文描述
3. 低权重维度：仅提供关键标签
4. Prompt 末尾的 "生成指令" 中强调高权重维度
```

### 5.3 起卦算法

- 验证变爻产生概率合理（约 50% 的起卦应有变爻）
- 验证相同输入产生相同输出（确定性）
