# RAG 升级规划

> 当前 MVP 不使用向量检索。本文件只记录未来升级条件，避免把规划误写成现行实现。

## 1. 当前状态

MVP 检索方式固定为：

- 本地 JSON 条目
- 基于节气、体质、情绪、生活标签的规则打分
- 取 Top 5 注入 Prompt

这已经满足当前产品目标，不额外引入 embedding、向量库或召回评估系统。

## 2. 何时考虑 RAG

只有满足以下条件，才启动 RAG 评估：

1. 本地知识条目超过 150 条
2. 规则检索开始频繁出现“相关但不够准”的问题
3. 已准备好人工标注的评估集
4. 有能力维护向量更新与质量监控

## 3. 升级目标

RAG 的目标不是“更高级”，而是解决两类问题：

- 更好地理解组合语境，例如“清明 + 疲惫 + 久坐”
- 降低纯手工标签检索的维护成本

## 4. 预期架构

升级后推荐保留混合检索，而不是完全替换规则检索：

```text
规则检索
  -> 保障节气与体质的显式命中
向量检索
  -> 补充语义相关条目
融合排序
  -> 取 Top 5 注入 Prompt
```

## 5. 进入实施前必须补齐的内容

- 稳定的知识条目 schema
- 至少 20 组人工评估样本
- 命中率和排序效果的验收指标
- 成本预算和回滚方案

## 6. 当前明确不做

- 当前版本不接入 pgvector
- 当前版本不写 embedding 脚本
- 当前版本不把模型查询文本暴露成独立接口
