# 舌象输入升级规划

> 当前 MVP 不包含舌诊功能。本文件只说明后续可能的升级路线。

## 1. 当前状态

MVP 主链路没有舌象输入，也不上传舌头照片。

原因：

- 当前产品目标是验证“每日建议卡”是否成立
- 舌象输入会显著增加合规、误判和交互成本
- 没有标注数据和人工评估前，不适合把拍照分析写成功能承诺

## 2. 可选升级顺序

如果未来确实需要舌象输入，顺序固定为：

1. 手选示意图
2. 明确用户价值后再评估拍照识别
3. 拍照识别前先完成隐私告知和准确性验收

## 3. 手选示意图阶段

仅作为可选补充输入，且必须满足：

- 不进入首次问卷主链路
- 不影响用户完成每日生成
- 输入值只允许 `option_a` / `option_b` / `option_c`
- 只用于建议细化，不改变产品边界

## 4. 拍照识别阶段的前置条件

只有同时满足以下条件才可立项：

1. 已完成单独隐私说明与用户同意流程
2. 已建立拍照失败和拒绝授权的完整降级路径
3. 已有基础标注数据和人工验收方案
4. 已明确“仅供参考，不作诊断”的产品呈现方式

## 5. 风险提醒

舌象拍照的主要风险不是技术实现，而是：

- 用户误把结果当成健康判断
- 图像采集引发额外隐私责任
- 弱光、角度、滤镜导致误判

因此在当前版本中，不把拍照识别写成已确认能力。
